# 구현 상태 v0.4.0

2026-10-10. 애플 건강 ZIP/XML의 러닝 요약 시험 지원을 추가했다. 실제 Apple 기기 파일은 미검증이며 [APPLE.md](APPLE.md)에 현재 범위·제한·검증 방법을 명시한다.

2026-10-09. 첫 화면을 최근 러닝 복기로 바꾸고 직접 고른 두 기록 비교, 선택형 기기 보관을 추가했다. 기존 기간별 분석은 분석 탭에 유지한다. ZIP 병합과 오프라인 새 실행은 후속 범위다.

## 최근 러닝 복기와 직접 비교

첫 화면은 최근 기록의 거리·시간·페이스, 시작 5분 이후 전후반 차이와 근거 구간으로 이어진다. 같은 길이의 최근/이전 28일 활동 일수를 보조로 보여주고 전체 합계·월별 거리는 접어 둔다. 장식용 상승 그래프를 제거했다.

두 러닝은 사용자가 직접 선택한다. 두 기록의 주 관측 범위에 공통으로 존재하는 경과시간 중 시작 5분 이후 최대 15분을 비교하며 최소 5분을 요구한다. 심박·속도 동시 관측의 시간가중 평균을 쓰고 커버리지 분모에 결측 시간을 포함한다. 70% 미만은 차이 문장을 만들지 않는다. 심박·페이스는 두 기록에 같은 축을 쓰는 1분 평균 그래프로 표시하며 각 원본 구간으로 이동·복귀할 수 있다. 기기 차이와 미상 정보를 표시한다. 같은 경과시간이 같은 코스나 강도를 뜻하지 않으며 체력 변화로 판정하지 않는다.

기존 기간별 비교는 차이의 방향 변경과 비교 조건 상태 변경을 별도로 기록한다. 모든 민감도 변형에서 방향이 같으면 그 관측과 조건 한계를 따로 설명한다. 기존 수치 계산은 바꾸지 않았다.

## 데이터 흐름과 제한

`삼성헬스 File → 앱 Worker → ZIP 중앙 목록 → exercise CSV → 러닝 1002 → 연결 JSON 순차 읽기 → 품질·안정 창·소형 집계 → UI`

ZIP 전체를 arrayBuffer로 가져오지 않는다. Worker에서 원본 File과 참조를 보관한다. 취소·초기화는 Worker를 종료하고 상세 읽기는 직렬화하며 대기 요청은 최신 것만 유지한다. requestId로 오래된 응답을 무시한다. 모든 러닝의 전체 시계열을 React에 복사하지 않고, 선택한 기록의 원본 정규화 포인트만 상세로 반환한다. v0.1의 시간 정보 없는 PaceBin은 성장 계산에 사용하지 않으며 Worker 응답에서 비운다.

상세 캐시는 최대 3회·추정 32 MiB, 프로필 입력은 약 50만 표본으로 제한한다. 제한은 다음 기록을 읽기 전 적용해 한 기록의 최대 10만 포인트만큼 초과할 수 있다. 메모리 추정치는 OS 보장 상한이 아니다. 긴 공백 안의 모든 60초 창을 반복 생성하지 않고 실제 인접 관측 주변만 평가한다.

압축 ZIP 512 MiB, 엔트리 10만, CSV 16 MiB·5만 행, JSON 8 MiB·10만 포인트·중첩 깊이 16, 작업 중 선택적 압축 해제 출력 128 MiB 제한을 유지한다. 선언 크기와 실제 writable 출력 바이트를 검사한다. 경로 traversal, 절대/중복 경로, 모호한 참조, 암호화, CRC 손상을 처리하지 않는다. 외부 URL 참조를 fetch하지 않으며 무관한 파일의 선언 출력 크기 합으로 정상 내보내기를 거절하지 않는다.

애플 건강은 별도의 streaming XML 경로로 러닝 요약만 정규화하며 `source: apple`을 보관·복원한다. ZIP 512 MiB, XML 압축 해제 후 1 GiB를 지원한다. 원본 이름·기기 문자열은 익명 출처 그룹으로 바꾸고 버린다. 두 애플 러닝은 전체 요약 표로 비교하며 시계열 분석 결과를 만들지 않는다.

## 정규화와 품질

- 주 CSV는 정확한 basename으로 찾는다. 복수 주 CSV를 임의 병합하지 않는다. BOM·메타데이터·CRLF·따옴표·명시적 별칭·마지막 빈 열을 처리하고 유의미한 추가 열/날짜 오류의 제외 수를 표시한다.
- UTC·명시 시간대 문자열을 epoch로 처리하며 time_offset은 현지 날짜에 적용한다. 미확인 수치 offset 단위를 추측하지 않는다. 시간대 미상 기록은 UTC 날짜로 표시하고 날짜별 분석에서는 제외한다.
- 음수·비유한 값은 제외한다. HR=0은 결측, speed=0은 정지로 보존한다. 높은 양수 HR만으로 삭제하거나 위험 판정하지 않는다. 동일 epoch의 보완 필드는 병합하고 충돌은 null로 유지한다.
- JSON interval/cumulative 거리 후보는 CSV 총거리로 검증한다. 둘 다 맞거나 불일치하면 unknown이며 미확정 구간거리는 만들지 않는다.
- UUID는 Worker 내부 중복 처리용이다. 원본 deviceuuid는 파일 안에서 같은 값을 연결하는 데만 쓰고 UI에는 `기기 A/B/…` 익명 그룹만 보낸다. 이를 실제 시계 모델로 추정하지 않는다.
- 60초 미만, 운동시간/시각 모순, 요약 페이스 2:00/km 미만, 상세 표본이 충분할 때 요약 평균속도가 상세 최고속도의 1.5배를 넘는 기록은 요약 시간·거리·페이스를 보류한다. 원본 값과 근거는 상세에서 확인한다. 짧은 분할 기록은 직접 포함할 수 있지만 잘못된 필드를 유효하게 만들지는 않는다.
- 요약이 보류돼도 유효 상세 관측은 별도로 사용할 수 있다. 요약 포함 여부와 성장 제외 여부를 따로 관리하고 변경 시 입력 revision을 올려 결과를 다시 계산한다. 일반 목록에서 기록을 삭제하지 않는다.

총량은 지표별 유효 집합의 합이다. 전체 결측은 null, 평균 페이스는 시간·거리가 함께 유효한 동일 집합의 합 비율이다. 품질 적용 결과와 원본 합계를 함께 확인할 수 있다.

## 상세와 그래프

기본은 심박 240px + 페이스 110px의 나눠 보기다. 케이던스는 펼치며 겹쳐 보기 240px와 독립 Y축을 유지한다. 보기·눈금·선택 timestamp·고정·확대 범위를 보존한다. 겹쳐 보기의 눈금 지표만 바꿀 때 선 위치는 바뀌지 않는다. 커서는 원본 시각을 이진 탐색하고 requestAnimationFrame으로 갱신한다. 표시 데이터와 Plot을 memo로 분리한다. 핀치는 제공하지 않는다.

원본 HR 선과 표시용 60초 시간가중 중앙값 추세를 구분하며 추세를 끌 수 있다. 추세는 연속 관측 안에서 실제 관측 30초·커버리지 70%를 요구한다. 표시를 최대 약 1,000개 포인트로 줄이면서 피크와 결측 경계를 보존한다. 분석은 원본으로 계산하며 공백·마지막 표본 뒤를 연장하지 않는다. 고립된 원본 관측은 점으로 표시한다.

심박 축은 최소 5bpm 여백·최소 폭 20bpm이다. 페이스는 주 표시 범위의 달리기 관측이 3분·유효 속도 시간의 60% 이상일 때 시간가중 P2–P98 ±15초/km, 최소 폭 60초/km로 집중한다. 바깥 관측은 표식·목록·전체 축 전환으로 확인하며 계산에서는 버리지 않는다. 확대 중 Y축은 고정한다.

큰 공백으로 나눈 그룹 중 하나가 관측시간 80% 이상·5분 이상이고 전체 경과가 그 그룹의 3배를 넘으면 주 그룹에 집중한다. 전체 경과와 모든 그룹으로 돌아갈 수 있다. 지배적인 그룹이 없으면 전체를 유지하고 차트 위에 그룹 선택을 제공한다. 그룹을 바꾸면 페이스 축·초중후반 요약의 기준을 그 그룹으로 바꾸고 이후 확대 중에는 축을 유지한다. 공백을 누르면 관측 없음으로 표시하며 멀리 있는 포인트로 이동시키지 않는다.

초중후반과 임의 선택 구간은 실제 시간 경계를 나눈다. 경계에 걸친 인접 관측 dt를 정확히 잘라 가중하고 커버리지 분모에 미관측 시간을 포함한다. 지표별 커버리지 70% 미만은 대표값을 보류한다. 관찰·사용자 HR 기준·전후반 통계에서 실제 구간으로 확대할 수 있다.

## 성장 비교

- 기본은 마지막 적격 관측 기준 최근 28일과 직전 28일이며 14/56일·사용자 지정 길이·종료일을 지원한다. 기간 길이를 같게 유지한다.
- 시작 5분 이후 속도 안정성 문맥 120초, 뒤쪽 60초를 분석 창으로 쓴다. 첫 기본 창은 6–7분이다. 속도 커버리지 80%, CV ≤8%, 앞뒤 평균 차이 ≤5%, 긴 공백·1.8m/s 미만·20% 초과 속도 전환 없음, 동시 관측 80%·4표본을 요구한다. 후보는 목표와 독립적으로 안정 3창·실제 180초를 요구한다.
- 같은 속도 부근의 HR은 목표 속도 ±8% tricube 가중, 같은 HR 부근의 페이스는 HR ±10bpm 가중으로 평균 속도를 구한 뒤 페이스로 바꾼다. 후자는 HR 비교를 역산하지 않는다.
- 각 5분 운동 시점 구간에서 전체 안정 관측시간으로 러닝 기여도 q를 정규화해 한 러닝의 최대 가중치를 1로 제한한다. 기간은 공통 시점 구간을 동일 비중으로 합친다. 공통 구간은 최소 2개이며 슬라이더 이동 중 고정한다.
- 공통 시간가중 P10–P90 범위 안에서만 계산한다. 실제 속도 차이 ≤1%(같은 HR 질문은 HR 차이 ≤2bpm), 실제 운동 시점 차이 ≤60초를 검사한다. 공통 익명 기기 하나를 기본으로 제안하고 혼합·미상은 조건 차이를 표시한다.
- 비교 가능: 각 기간 5회·3일·유효 러닝 5·가중 600초·각 구간 유효 3. 참고용: 3회·2일·유효 3·가중 300초·각 구간 유효 2. 그보다 부족하면 차이 숫자를 강조하지 않는다. 유효 러닝은 `(Σq)²/Σq²`다.
- 폭 6/8/10%(HR 8/10/12bpm)와 러닝 한 회씩 제외한 결과에서 방향 또는 지원/조건 상태가 바뀌면 설정 영향 있음으로 표시한다. 훈련 효과나 체력 향상을 단정하지 않는다. 기온·코스·수면은 보정하지 않는다.
- 날짜별 점은 러닝 한 회의 요약, 점선은 기간 대표값, 띠는 q 가중 러닝별 P25–P75 관측 편차다. 신뢰구간으로 표현하지 않는다. 지원량·실제 조건·사용/제외 기록·원본 안정 창을 펼치고 상세로 이동한다. 복귀하면 비교 조건과 스크롤을 유지한다.

Worker가 안정 창과 기본 집계를 만들고, 메인 스레드의 memo가 작은 창 집합에 순수 비교 함수를 적용한다. 입력 revision·조건 변경 때 다시 계산한다. 전체 원본을 슬라이더마다 스캔하지 않는다. 실제 휴대폰 p95 성능은 아직 측정 전이며 필요 시 비교 계산도 Worker로 옮긴다.

다섯 질문은 비슷한 속도의 HR, 비슷한 HR의 페이스, 운동시간/이어진 달리기, 전후반 유지, 활동 일수/꾸준함이다. 주·월의 실제 날짜와 부분 기간을 표시하고 빈 주는 측정 없음으로 유지한다. 한 날짜의 분할 운동은 활동 일수 한 번으로 센다. 일반 전후반 비교는 시작 5분 이후 각 절반 5분·동시 관측 70% 조건이며 HR·속도를 따로 표시한다. 엄격한 드리프트는 연속 20분·커버리지 80%·속도 차이 5% 조건의 보조 지표로 유지한다. 기록 한 회만으로 드리프트 추세를 만들지 않는다.

## 개인정보·리포트·설치

기본은 메모리 전용이다. 명시적으로 ‘이 기기에 러닝 보관’을 누르면 정규화된 러닝 요약·프로필·상세와 계산 버전을 IndexedDB에 저장한다. 원본 ZIP·원본 식별자·GPS·프로필·사진은 보관하지 않는다. 임시 세대에 상세를 순차 저장하고 모두 성공한 뒤 활성 스냅샷을 교체한다. 실패하면 이전 스냅샷을 유지하며, 사용자 초기화/저장 오류 시 임시 데이터를 정리한다. 강제 종료로 남은 임시 데이터는 시작 화면의 기기 보관 관리에서 전체 삭제할 수 있다. 최대 60만 상세 포인트를 보관하고 저장소 한도 오류를 표시한다. 복원 후 원본 ZIP 없이 상세와 직접 비교를 읽을 수 있다. 분석 설정 변경도 반영하며, 형식/계산 버전이 다르면 새 ZIP을 요청한다. 보관은 현재 파일로 교체하며 병합하지 않는다. localStorage는 테마·그래프 보기뿐이다. 외부 폰트/CDN/분석/오류 수집이 없고 GPS·사진·프로필·메모를 모델에 넣지 않는다. 배포와 preview CSP는 `connect-src 'none'`이다. 정적 앱 전달에는 호스팅 요청 기록이 발생하지만 선택한 ZIP과 분석값은 보내지 않는다.

JSON 리포트에는 계산 버전, 입력 revision, 기간, 목표·폭·시점·기기 필터 유형, 결과 상태·지원량·민감도, 원본/품질 적용 합계, 사용자 포함·제외 여부를 기록한다. UUID·원본 기기 ID·GPS·원본 파일명은 넣지 않는다. 날짜·건강 수치를 포함하므로 개인 자료다. 초기화/종료는 Worker·상태·캐시·input·object URL 참조를 해제하지만 물리 메모리 즉시 삭제를 보장하지 않는다.

매니페스트·아이콘·iOS 시작 이미지·로딩 화면은 유지한다. Service Worker·오프라인 새 실행·ZIP 병합은 없다. 선택형 기기 보관을 완료하면 재열기에 ZIP이 필요하지 않다. [PWA 범위](PWA.md).

## 검증과 남은 확인

애플 건강은 합성 XML/ZIP만 검증했다. Apple 기기에서 생성한 실제 파일과 실기기 테스트는 미완료다. 기존 삼성헬스 실제 파일 검증 결과를 애플 호환성의 근거로 사용하지 않는다.

- TypeScript/Vite production build, Vitest 59개, Playwright 16개(모바일 Chromium/WebKit) 통과.
- 단위 검증: 품질/원본 분리, 불규칙 간격·경계 dt·표본 밀도 불변, 긴 공백, 표시/추세 원본 보존, 안정 창·독립 러닝 가중, 연속 목표 변경, 혼합 기기·부족 자료, 같은 HR의 직접 속도 계산, 날짜별 활동/빈 주. 기존 파서·ZIP·피크·결측 검증도 유지한다.
- 브라우저 검증: 보기/축/커서/구간 보존, 320px 넘침, 합성 비교 방향, 실제 근거 구간·복귀·제외·재포함·다섯 질문, 파일 재선택/취소, 리포트 식별자 제외·계산 메타데이터, 테마/초기화, PWA 연결. 동일 CSP에서 외부 요청·데이터 전송과 Service Worker/Cache Storage/건강 localStorage 없음 확인. 기본 비보관, 선택 저장, 새로고침 복원, 복원된 상세·비교, 삭제 취소와 전체 삭제 후 빈 저장소를 추가 확인했다.
- 제공된 실제 ZIP의 선택 읽기·품질·집계·공백·페이스 축·안정 창/비교 검증을 로컬에서 수행했다. 90/120/180초 문맥과 5/8/12% CV 지원량도 기록했으며 기본 문턱을 결과 수에 맞춰 바꾸지 않았다. 개인 수치·스크린샷은 `.local/`에만 두며 이 하나의 ZIP으로 모든 삼성헬스 버전 지원을 주장하지 않는다.
- 실제 ZIP의 390×844 데스크톱 모바일 viewport에서 첫 상세 심박 차트, 바깥 페이스 관측, 요약·성장 그래프와 콘솔을 확인했다. 이는 실제 휴대폰 성능 검증이 아니다.
- Samsung Internet/실제 Android Chrome·iPhone Safari의 OS 파일 선택창, 터치 스크롤, 설치 화면, 메모리 압박과 500ms/100ms 성능 목표의 p95는 실기기 검증 전이다.
- 푸시와 별개로 운영 URL의 배포 완료·보안 헤더·ZIP/Worker 동작을 확인해야 한다. 자동화 WebKit을 실기기 Safari와 동일시하지 않는다.
