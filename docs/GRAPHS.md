# 그래프 경험 스펙 v0.2

> v0.2의 정책·화면·계산은 [개편 스펙](REVISION_SPEC.md), 실제 구현과 검증 범위는 [구현 상태](IMPLEMENTATION.md)를 참조하세요. 아래는 초기 설계 기록입니다.

2026-10-08. 미니멀 기록장 디자인 확정 후 작성한 구현 전 초안. 시안은 실제 한 기록의 관측값을 사용하며, 최종 파서/분석 모듈을 대체하지 않는다.

## 1. 첫 화면에서 읽혀야 하는 것

상세를 열면 전체 러닝 시간 범위의 심박·페이스·케이던스를 같은 폭, 같은 경과시간 축으로 세로 배치한다. 사용자의 추가 요청으로 `나눠 보기 / 겹쳐 보기` 토글을 제공한다. 모바일에서도 세 지표를 번갈아 켜야만 비교하는 방식으로 만들지 않는다. 긴 기록은 화면 해상도에 맞게 선을 줄이되 피크·결측 경계를 보존한다.

### 나눠 보기와 겹쳐 보기

기본은 나눠 보기. 겹쳐 보기는 같은 시간축의 한 영역에 세 선을 표시한다. 단위가 다른 지표를 하나의 숫자 축으로 해석하지 않는다. 각 지표는 전체 기록의 독립적인 축 범위를 사용하고, 빠른 페이스가 위쪽이라는 방향은 두 모드에서 같다.

모바일에서 세 Y축을 나란히 두면 표시 영역이 줄어드므로 눈금은 선택한 지표 하나를 표시하고, 세 선 각각의 축 범위와 단위는 범례 아래에 항상 표시한다. `Y축 눈금` 선택은 눈금/가이드 기준만 바꾸며 선의 높이·범위·선택값은 바꾸지 않는다. 심박·페이스·케이던스 선은 색과 실선/점선으로 구별한다.

겹쳐 보기의 목적은 변화 시점 비교다. 선이 교차하거나 높이가 같아도 같은 측정값이나 센서 일치를 뜻하지 않으며, 이를 그래프 가까이에 짧게 설명한다. 실제 bpm/페이스/케이던스 수치는 공통 시점 표시에서 확인한다. 센서 패턴 분석은 원본 값으로 별도 수행한다.

보기 전환 시 확대 범위, 선택 시점, 고정 상태를 그대로 유지한다. 마지막 보기 선호만 개인 데이터 없는 설정으로 저장할 수 있으며 건강 데이터는 저장하지 않는다. 보기 전환과 축 선택은 파일 재분석을 유발하지 않는다.

구현 상태는 하나의 공통 모델로 관리한다: `layout(split/combined), axisMetric, selectedTimestamp, pinned, windowStart, windowEnd`. 그래프별로 별도의 선택/확대 상태를 만들지 않는다. 로컬 저장 허용 범위는 layout과 axisMetric 같은 UI 선호뿐이며, 선택 시각/확대 범위는 현재 파일을 읽는 탭의 메모리에 둔다.

각 그래프의 지표명과 단위는 항상 보인다. 주 정보는 선과 축이며, 넓은 면적 채우기·3D·장식·기본 최대/최소 라벨은 사용하지 않는다. 선 두께는 1.5~2px를 기본안으로 둔다. 초기 진입에서 선이 왼쪽부터 그려지는 애니메이션은 생략한다.

그래프 영역의 높이를 데이터 로딩 전에 확보한다. 로딩 중에는 동일한 레이아웃의 빈 축/상태를 표시하고, 크기와 데이터가 준비되면 한 번에 실제 그래프를 표시한다. 요약 기록을 먼저 이용할 수 있어도 상세 시계열이 준비되기 전에는 그래프를 만들어내지 않는다.

현재 구조 검사의 대표 측정 간격은 약10초다. 확대는 관측값을 더 크게 보여주는 기능이며, 원래 없는 1초 단위 값이나 피크를 생성하지 않는다.

## 2. 축과 선

- X축: 러닝 시작부터 경과 분:초. 기본은 전체 실제 경과시간. 360px 이하에서 눈금 3~4개 수준으로 줄이고 양 끝 숫자의 여백을 확보한다.
- Y축: 지표별 독립 축. 전체 유효 관측값 범위에 여백을 둔다. 심박/케이던스는 반드시 0부터 시작할 필요가 없고 축 범위를 명시한다.
- 페이스: 초/km로 계산하고 분:초/km로 표시한다. 빠른 값이 위쪽. speed=0의 페이스는 수치로 그리지 않고 정지/결측 상태를 설명한다.
- 기본 연결은 직선. 매끈한 곡선이 실제 측정값보다 높은 피크를 만들거나 변화를 숨기지 않도록 한다.
- 결측값과 허용 간격을 넘는 공백은 선을 끊는다. 공백의 심박·페이스·케이던스를 0으로 만들거나 앞 값으로 연장하지 않는다.
- 구간을 확대해도 Y축은 기본적으로 전체 기록 범위를 유지해 같은 변화가 과장되지 않도록 한다. 구간별 축 자동 맞춤은 필요성이 확인되면 별도 표시 옵션으로 검토한다.
- 월별 운동량은 0 기준 막대, 성장 날짜별 심박은 실제 기록별 점과 주/월 대표값으로 표시한다. 미완료 월을 표시하고 기간별 표본 차이를 함께 제공한다.

## 3. 시점 확인

| 입력 | 화면 동작 |
| --- | --- |
| 데스크톱 포인터 이동 | 같은 관측 시각의 3개 커서와 상세값을 동기화 |
| 클릭 / 모바일 탭 | 가장 가까운 실제 관측 시점 고정. 실제 경과시각을 표시 |
| 모바일 수평 이동 | 시점을 따라가기. 세로 스크롤은 브라우저 기본 동작 유지 |
| 키보드 / 시점 슬라이더 | 이전/다음 실제 표본 이동. 화면을 직접 누르기 어려울 때 동일 정보 확인 |

표시값은 그래프 밖 한 곳에 `경과시각 · 심박 · 페이스 · 케이던스`로 정리한다. 작은 툴팁이 선이나 손가락 아래에서 필수 정보를 가리지 않도록 한다. 초기에 임의의 표본을 대표값으로 선택하지 않는다.

고정 후 포인터를 옮겨도 선택 시점은 유지한다. 다른 시점을 탭하면 새 시점으로 고정하며 `선택 해제`로 탐색 상태로 돌아간다. `전체 구간` 복귀는 확대와 고정 시점을 모두 초기화한다.

세 지표는 같은 실제 관측시각의 값을 먼저 사용한다. 그 시각에 없는 지표는 `—`. 다른 시각의 최근 측정값을 보여주는 기능을 추가하면 그 측정시각과 차이를 표시하며 동시 관측이라고 부르지 않는다. 시안은 보간하지 않는다.

호버 업데이트와 지속적인 드래그는 화면 읽기 프로그램에 매 프레임 알리지 않는다. 탭 고정, 키보드로 확정한 시점과 구간 변경에는 간결한 안내를 제공한다.

## 4. 구간 선택과 확대

`구간 선택`을 누르면 시작/끝 조작 컨트롤을 표시한다. 모바일에서는 44px 이상 핸들 또는 두 개의 명확한 시간 슬라이더를 제공한다. 정확한 경계는 시간 입력으로도 선택할 수 있게 한다. 최소 유효 구간은 서로 다른 관측시점 2개이며 통계의 적격 조건과 별도다.

확대된 X축은 3개 그래프에서 항상 동일하다. 선택한 시간 범위를 화면에 남기고 `전체 구간`으로 원래 범위에 복귀한다. 범위 밖의 고정 커서는 해제한다. 핀치가 없어도 전체 기능을 사용할 수 있어야 하며, 핀치는 실기기 충돌 검증 뒤 추가한다.

구간별 통계는 원본 유효 관측과 명시된 계산 기준으로만 생성한다. 다운샘플된 화면 점을 통계 입력으로 쓰지 않는다. 관측 수·시간 커버리지·결측 이유를 함께 제공한다. 초기 시안에는 구간 범위와 관측 수만 표시하고 평균·구간거리는 검증된 계산 모듈을 연결한 뒤 제공한다.

## 5. 초기 렌더링과 반응성 구현 원칙

- 차트의 크기와 다운샘플링을 준비한 후 첫 그림을 표시한다. 초기 0폭 그래프와 반복적인 축 변경을 피한다.
- 통계/집계·다운샘플링은 Worker에서 수행한다. 커서 이동은 준비된 관측 배열을 검색하고 지표값/커서만 갱신한다.
- 포인터가 움직일 때 파일 재읽기, 원본 배열 전체 정렬, React 화면 전체 재렌더를 하지 않는다. 원본 포인트와 표시 포인트를 분리한다.
- requestAnimationFrame으로 시점 갱신을 모아 한 프레임에 하나로 적용하고, ResizeObserver 갱신도 실제 크기 변경 시만 수행한다.
- 경로/축 레이아웃과 커서 오버레이의 업데이트를 분리한다. 안정된 시간 키를 사용하고 오래된 Worker 응답은 requestId로 차단한다.
- 대용량은 픽셀 기반 점 수 제한과 피크/공백 보존을 적용한다. 구간 확대 시 그 범위의 원본으로 표시 데이터를 다시 생성한다.

기술 검증 후보는 Recharts다. 특정 라이브러리의 기본 툴팁/Brush에 UX를 맞추지 않는다. 요구한 동기 커서·정확한 결측·터치·선택 구간이 구현 가능한지 작은 기술 검증을 하고, 부족하면 차트 위 공통 인터랙션 계층을 둔다. 실제 제품은 라이브러리 파일을 번들에 포함하며 원격 차트 서비스에 건강 데이터를 보내지 않는다.

## 6. 검증 기준

아래 시간 목표는 **달성 여부를 측정할 목표**이며 현재 성능 보장이 아니다. 기준 기기와 기록 점 수를 함께 기록한다.

- 이미 상세 데이터가 준비된 기록: 탭 진입 후 첫 유효 그림까지 500ms 이내 목표. ZIP 읽기 시간은 따로 측정.
- 시점 선택: 입력부터 커서/표시값 갱신까지 100ms 이내 목표. 모바일 연속 탐색에서 긴 프레임 중단을 점검.
- 320/360/390px, 큰 글자 설정, 밝은/어두운 모드에서 단위·눈금·선택값 겹침이나 가로 넘침 없음.
- 실제 시각과 커서값 일치, 세 그래프 동기화, 결측의 `—`, 확대 후 복귀, 범위 밖 선택 처리 검증.
- 겹쳐 보기/나눠 보기 전환에 선택 시점·확대 범위·고정 상태 유지. Y축 지표 변경에 선 위치와 실제 값 유지. 두 모드 모두 모바일 넘침 없음.
- 모바일 세로 스크롤과 수평 탐색의 충돌, 탭 취소, 핸들 조작을 실기기에서 확인.
- 정지, 긴 공백, 동일 시각 충돌, 상세 없음, 극단값, 짧은 기록, 장시간 기록으로 초기 렌더링을 확인.

시안에서 확인한 브라우저 동작과 최종 React/Recharts 구현의 성능을 동일하게 취급하지 않는다.
