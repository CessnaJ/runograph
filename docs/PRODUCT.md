# runograph 제품 기획 v0.1

> v0.2의 정책·화면·계산은 [개편 스펙](REVISION_SPEC.md), 실제 구현과 검증 범위는 [구현 상태](IMPLEMENTATION.md)를 참조하세요. 아래는 초기 설계 기록입니다.

작성일: 2026-10-08 (한국 시간). 상태: 논의용 초안. 세 목적을 큰 탭으로 제공하고, 미니멀 기록장 디자인을 사용자 선택으로 확정했다. 그래프의 초기 렌더링과 이후 인터랙션을 우선 구체화한다.

## 1. 제품이 답할 질문

사용자 방향: **운동량 요약, 개별 러닝 분석, 성장 분석을 모두 큰 탭으로 제공한다.** 삼성헬스보다 읽기 쉬운 정보 배치와 시인성을 주요 제품 목표로 둔다.

탭 제안은 `요약 · 러닝 · 성장`이다. 요약은 운동량과 월별 변화, 러닝은 기록 목록과 상세, 성장은 같은 페이스의 심박 반응과 장기 변화를 다룬다. 성장만 우선하는 제품으로 좁히지 않는다.

심박 반응과 효율 수치는 관찰값이다. 훈련 효과나 건강 상태를 단정하지 않는다. 날씨·경사·수면·센서 착용·기기 변경 등 통제하지 못한 조건을 비교 한계로 명시한다.

## 2. 범위와 개발 단계

단계는 개발 순서이며, 아래 후반 기능도 목표 범위에 포함된다.

| 단계 | 제공 결과 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| 설계 | 실제 ZIP 구조, 파서 계약, 지표 정의, 모바일 화면 시안 | 사용자 우선순위·디자인 결정 및 주요 미확정 항목 정리 |
| 데이터 기반 | ZIP 선택·진행·취소·경고, 러닝 목록, 정규화 | 실제 ZIP 로컬 검증 및 합성 포맷 테스트 통과 |
| 기본 분석 | 대시보드, 상세 3종 그래프의 나눠/겹쳐 보기, 구간 선택·통계 | 요약과 상세 출처가 분리되고 결측·정지가 왜곡되지 않음 |
| 성장 및 관찰 | 페이스-심박 비교, 주월 추세, 드리프트, 특이 구간 | 표본·비교 조건·제외 이유가 함께 표시됨 |
| 출시 | 모바일 검증, 모드 전환, 리포트, 초기화, Vercel | 빌드·테스트·개인정보·실기기 검증 통과 |

별도 제안 범위: 로그인, 서버 처리, GPS 지도, 운동 처방, AI API, 자동 건강 판정, 여러 ZIP 병합, 앱 설치/PWA는 첫 버전에서 제외한다. 필요 시 별도 논의한다.

## 3. 지표의 의미

모든 지표에 기간, 단위, 출처, 제외 기록 수를 제공한다. 결측은 `—`로 표시하고 0으로 채우지 않는다. 전체 시간과 거리에는 각각의 유효값을 사용하되 평균 페이스에는 시간·거리가 둘 다 유효한 동일한 기록 집합만 사용한다.

| 화면 지표 | 제안 계산 정의 |
| --- | --- |
| 총 러닝 횟수 | 중복 제거 후 선택 기간에 속한 러닝 기록 수 |
| 총 거리 | 유효한 세션 요약거리 합 / 1000, km |
| 총 운동시간 | 유효한 CSV duration 합, 경과시간과 별도 |
| 전체 평균 페이스 | 유효한 요약 운동시간 합 / 동일 집합의 거리 합, 초/km; 개별 페이스 산술평균과 구분 |
| 러닝 중앙 페이스 | 기록별 요약 운동시간/거리의 중앙값; 기록마다 동일 가중치 |
| 전체 평균 심박 | 유효한 상세 심박의 관측 구간 길이로 가중; 해당 구간이 없는 세션은 제외 |
| 기록별 평균 심박 | CSV 원본 요약값을 먼저 표시. 상세 재계산값은 출처를 구분해 별도로 제공 |
| 최대 심박 | 선택 기간 유효 CSV 최대값의 최대. 유효 요약값이 없을 때만 상세 관측 최대값을 대체 출처로 표시 |
| 월별 변화 | 기록 당시 현지 날짜로 거리·횟수·운동시간 집계; 페이스 추세는 기록별 중앙값 |

상세 심박 평균이 없는 경우 전체 평균을 요약 평균으로 조용히 대체하지 않는다. 별도 `요약 심박 평균`을 제공할 경우 유효 CSV 평균값을 그 기록의 duration으로 가중하고 계산 기준을 명시한다. 서로 다른 방법을 혼합하지 않는다.

요약 duration과 end-start는 다를 수 있다. 자동으로 동일시하지 않으며, 상세 시간축은 시작 후 실제 경과시간으로 표시한다.

## 4. 성장 분석

아래 숫자는 의학적 기준이 아닌 **제품 분석 조건 제안**이다. 구현 전 실제 데이터 품질과 검증 결과에 따라 조정하고, 계산 버전을 기록한다.

- 페이스-심박 산점도: 유효한 동시 측정쌍을 사용. 화면의 점 수는 줄일 수 있으나 계산은 원본 유효 표본에서 수행한다. 터치한 점에서 기록 상세로 이동한다.
- 페이스 구간: 사용자 지정 중심 페이스 ±15초/km를 초기 폭으로 제안. 해당 구간에서 기록별 심박 중앙값을 구한 다음 기록 간 중앙값을 비교한다.
- 날짜별: 기록당 한 점. 주간은 기록 현지 날짜 기준 월요일 시작, 월간은 달력 월. 대표값은 기록별 심박 중앙값들의 중앙값이며 원본 표본을 한데 합쳐 긴 러닝을 과대 반영하지 않는다.
- 워밍업 제안 제외: 시작 5분. 결측과 정지, 걷기 추정, 급격한 속도 전환 인접 구간도 제외. 심박을 임의 시간만큼 이동시키지 않는다.
- 기록 적격 제안: 페이스 구간 내 유효한 심박·속도 쌍 20개 이상, 관측시간 3분 이상, 비교 구간 유효 커버리지 70% 이상.
- 기간 비교 제안: 각 비교 기간에서 적격 기록 3회 이상. 미만이면 추세 결론 없이 관측값과 `데이터 부족`을 표시한다. 기준 충족도 통계적 유의성이나 인과를 뜻하지 않는다.
- 모든 결과에 러닝 횟수, 원본 유효 표본 수, 유효 관측시간, 제외 이유, 페이스 구간과 기기별 필터 상태를 표시한다.
- 기기 식별자는 내부 그룹에만 사용하고 화면에는 `기기 A`처럼 익명 표시한다. 출처 미상과 다른 기기를 포함하면 비교 한계를 표시한다.

### 심박 드리프트 및 효율

연속 20분 이상, 유효 커버리지 80% 이상, 두 절반의 대표 속도 차이 5% 이하인 안정 구간을 초기 분석 조건으로 제안한다. 정지·긴 결측·속도 급변을 포함하는 구간은 제외한다.

각 절반에서 유효한 동시 관측쌍의 시간가중 평균 속도 / 시간가중 평균 심박을 계산해 E1, E2로 정의하고, 변화율은 `100 × (E1 - E2) / E1`로 표시한다. E1이 0 또는 결측이면 계산하지 않는다. `후반 효율 변화`라는 관찰로 설명하고 피로·질병 원인을 단정하지 않는다. 날짜별 효율 비교에도 같은 적격 기준을 적용한다.

## 5. 특이 구간 관찰

각 카드는 `관찰 · 시간 구간 · 근거 수치 · 계산 조건 · 제외/결측 · 한계`를 갖는다. 데이터가 부족하면 관찰을 생성하지 않는다. 적격 데이터가 없다는 상태와, 분석했지만 조건에 맞는 관찰이 없다는 상태를 구별한다.

| 유형 | 분석 조건 제안 | 표현과 한계 |
| --- | --- | --- |
| 설정 심박 이상 지속 | 사용자가 정한 bpm 기준 이상 관측이 60초 이상 이어짐. 결측을 연결하지 않음 | `설정한 심박 이상 구간`; 나이로 최대심박이나 위험선을 자동 생성하지 않음 |
| 짧은 심박 변화 | 30초 이하 유효 관측에서 20bpm 이상 변화. 변화량과 실제 시간 차이 표시 | `짧은 시간의 심박 변화`; 기록 간격보다 짧은 이벤트 검출 불가 |
| 심박-케이던스 유사 패턴 | 동시 유효쌍 30개·연속 3분 이상, 유사성 후보로 상관 ≥0.8 및 절대 차이 중앙값 ≤10 제안 | 두 값의 분산이 부족하면 계산 불가. 센서 간섭이나 cadence lock을 확정하지 않음 |
| 평소 대비 다른 심박 | 같은 페이스 구간의 이전 적격 기록 5회 이상, 기록별 중앙값과 MAD 기반 차이 검토 | MAD가 0이면 점수 생성 안 함. `개인 비교 기록보다 높은/낮은 심박`으로 설명 |
| 감속 뒤 심박 변화 | 유효 60초 창의 대표 속도 20% 이상 감소 후, 이어지는 유효 60초 창의 심박 변화 관찰 | `러닝 중 감속 후 심박 변화`. 운동 종료 후 회복심박과 구분 |

심박-케이던스 상관만으로 결과를 만들지 않는다. 값의 근접도, 지속시간, 관측 수와 함께 제공하고 실데이터에서 후보가 과도하면 조건을 재검토한다. 평소 대비 비교는 현재 기록을 기준 집합에서 제외한다. 여러 유형이 같은 구간을 가리키면 한 카드 안에 근거를 묶는다.

운동 종료 후 시계열을 별도로 읽지 않는 첫 버전에서는 회복심박(HRR)을 생성하지 않는다. 의료적 정상·위험·질환 등급, 임의의 건강 점수, 데이터 없는 통계 문장은 제공하지 않는다.

## 6. 저장 및 개인정보

- ZIP 선택은 파일 읽기다. 앱 문구는 `업로드` 대신 `ZIP 선택`, `기기에서 분석`을 사용한다.
- ZIP과 정규화 건강 데이터는 탭의 메모리에만 둔다. 새로고침이나 탭 종료 후 다시 선택해야 함을 안내한다. localStorage에는 테마와 개인 데이터 없는 UI 설정만 허용한다.
- IndexedDB, Cache Storage, Service Worker에 건강 데이터나 ZIP을 저장하지 않는다.
- 초기화는 작업 중단, Worker 종료, 파일 참조·차트·캐시·다운로드 객체 URL 해제와 시작 화면 복귀를 수행한다. 메모리 참조 해제이며 물리적 메모리의 즉시 삭제를 보장하는 표현은 쓰지 않는다.
- GPS 필드, 위치 JSON, 날씨 CSV, 프로필, 사진, 기기 이름·사용자 메모는 분석 대상으로 읽지 않는다. exercise CSV에 포함된 불필요한 필드는 정규화 단계에서 버린다.
- 외부 analytics, 오류 수집, 광고, 원격 폰트, 원격 차트 서비스, AI API를 넣지 않는다. 운영 코드에는 실제 데이터 로그가 없어야 한다.
- 정적 사이트의 HTML/JS 전달에는 호스팅의 일반 요청 처리가 발생한다. `파일 내용과 분석값을 보내지 않음`으로 설명하며 `네트워크 요청이 전혀 없음`으로 설명하지 않는다.
- 리포트 제안: 로컬 생성 JSON과 사람이 읽는 HTML. 데이터·날짜·지표 출처·표본·한계 포함. 이름, UUID, 기기 식별자, 원본 파일명, 위치, 자유입력 메모는 제외. 다운로드 직전에 포함 정보 표시. PDF는 첫 버전 후 별도 검토.

## 7. 검증과 완료 기준

Vitest: 메타데이터/BOM/CRLF/따옴표/추가 빈 열, 별칭 충돌, 타입 코드, UTC와 오프셋/현지 월 경계, 단위·0·결측, JSON 연결 누락/중복, 누적 및 구간 거리, 중복 시각, 품질 조건, 평균 가중 방식, 부족 데이터, ZIP 제한·경로·취소를 검증한다. 합성 데이터는 명확히 테스트 전용이며 사용자 분석에 섞지 않는다.

Playwright: 모바일 뷰포트의 파일 input 지정, 취소·재선택·실패 복구, 기록 검색/기간 필터, 상세 차트·동기 커서·구간 선택, 테마, 초기화·리포트를 검증한다. 앱 로드 후 외부 요청과 데이터 전송을 검사한다. 브라우저 자동화의 파일 지정은 실제 OS 파일 선택창 검증과 다르므로 후자는 실기기에서 확인한다.

실제 ZIP은 환경변수/로컬 경로로만 주입한다. 개인 결과는 `.local/`에만 저장하며 외부 CI에 업로드하지 않는다. 실제 기기에서 Samsung Internet/Android Chrome/iPhone Safari의 파일 선택, 취소, 터치 구간 선택, 재선택, 메모리 압박 후 복구를 확인한다. Playwright의 Chromium/WebKit 검증으로 실기기 지원을 단정하지 않는다.

출시 시 `npm run build` 및 핵심 테스트 통과. 배포 아티팩트에 ZIP/개인 데이터/개인 스냅샷이 없음. 저사양 모바일의 수용 한계와 실제 측정 환경·처리시간을 기록한다. 아직 성능 목표를 달성했다고 표현하지 않는다.

## 8. 배포

Vite 정적 빌드 `dist/`를 Vercel에 배포한다. 서버 함수, DB, 업로드 저장소, API 키는 필요 없다. 첫 버전 화면 전환은 해시 경로를 제안해 직접 진입 시 정적 라우팅 실패를 피한다.

Vercel Hobby는 개인·비상업 프로젝트에 적합한 무료 플랜이며 사용량 한도가 있다. 앱 파일 다운로드는 호스팅 사용량에 포함되지만 사용자가 선택한 ZIP 용량은 서버 전송량에 포함되지 않도록 설계한다. 무료 무제한이나 비용 영구 보장은 하지 않는다. 배포 시 최신 조건을 다시 확인한다.

공식 확인 자료: [Vercel Hobby](https://vercel.com/docs/plans/hobby), [Vite 정적 배포](https://vite.dev/guide/static-deploy.html).

## 9. 확정이 필요한 항목

1. 사용자 의견 반영: 세 목적을 모두 큰 탭으로 제공. 탭명/순서는 현재 `요약 · 러닝 · 성장` 제안.
2. 디자인 확정: 미니멀 기록장. 가독성은 특히 그래프 첫 표시와 이후 조작 경험에 집중한다.
3. 초기 버전의 메모리 전용 저장과 재선택 흐름 수용 여부.
4. 분석 적격 조건과 실기기 검증 결과에 따른 제한값 확정.

3은 개인정보 요구에 맞는 기본안이며, 4는 파서·검증 단계에서 수치 근거를 추가한다. 그래프 상세 화면은 GRAPHS.md와 실제 기록 기반 시안으로 검토한다.
