# Runograph 개편 확정 스펙 v0.2

2026-10-08 · 상태: **v0.2 A–C 구현 완료**. D(선택형 로컬 보관·병합)는 v0.3 범위다. 검증과 제한은 [구현 상태](IMPLEMENTATION.md)를 참조한다.

이 문서는 두 진단과 기존 소스를 종합한 v0.2 구현의 기준이다. 기존 PRODUCT.md, DESIGN.md, GRAPHS.md와 충돌하는 정책은 이 문서를 우선한다. IMPLEMENTATION.md는 실제 구현과 검증 범위를 기록한다.

## 1. 제품의 목표와 유지할 결정

사용자가 **한 번의 러닝에서 심박이 언제 달라졌는지, 여러 러닝 사이에서 무엇이 달라졌는지, 그 판단에 어떤 기록이 쓰였는지** 읽을 수 있게 한다.

- `요약 · 러닝 · 성장` 세 탭과 미니멀 기록장 디자인을 유지한다.
- React/TypeScript/Vite, Worker, 선택적 ZIP 읽기, 정적 배포 구조를 유지한다. 분석을 위해 서버나 AI API를 추가하지 않는다.
- 상세의 `나눠 보기 / 겹쳐 보기`는 사용자가 요청한 기능이므로 유지한다. 기본 나눠 보기에서 심박의 비중을 높인다.
- 모든 주요 화면은 **질문 → 관측 결과 → 그래프 → 사용한 기록/조건 → 계산 설명** 순서로 구성한다.
- 숫자가 달라진 것과 체력이 향상된 것을 구별한다. 결과 문구는 결정론적 템플릿으로 생성하고 관측 근거에 연결한다.

## 2. 두 진단을 종합한 최종 결정

| 쟁점                           | 최종 결정                                                     | 채택 이유                                                      |
| ------------------------------ | ------------------------------------------------------------- | -------------------------------------------------------------- |
| 디자인을 다시 바꿀 것인가      | 테마 유지, 장식적 제목 축소, 차트와 답의 위치 변경            | 두 진단 모두 정보 순서와 분석 모델을 핵심 문제로 확인          |
| 몇 초 차이 페이스 처리         | 안정 관측 구간에 부드러운 가중치 적용                         | 고정 구간 경계와 기록 적격 문턱이 비교 집합을 급변시킴         |
| 바로 LOESS를 도입할 것인가     | v0.2는 연속 가중 관측 평균과 조건 일치 검사. 회귀 보정은 보류 | 관측이 적거나 분포가 다른 상태에서 매끈한 곡선만 추가하지 않음 |
| 날짜별 변화와 산점도           | 날짜별 러닝 점과 두 기간 비교를 기본, 전체 산점도는 보조 탐색 | 시간 변화와 기록 간 편차를 먼저 읽어야 함                      |
| 드리프트가 거의 안 나오는 문제 | 일반 전후반 통계와 엄격한 드리프트를 별도 지표로 분리         | 조건을 낮춰 결과 개수만 늘리지 않고 사용 가능한 설명을 제공    |
| 이상한 기록                    | 원본 보존, 지표별 품질 상태와 사용 여부 관리                  | 파싱 성공과 비교 가능 여부는 다름                              |
| 다시 ZIP을 고르는 문제         | 핵심 분석 개편 이후 선택형 기기 내 저장·병합 구현             | 유용한 분석을 먼저 완성하고 저장 정책은 별도 단계로 변경       |

연속 가중 평균은 국소회귀보다 단순한 관측 요약이다. 정확히 같은 속도의 생리 반응을 추정했다고 표현하지 않는다. 가까운 관측에 더 큰 비중을 주는 원리와 국소회귀의 데이터 요구량은 [NIST 설명](https://itl.nist.gov/div898/handbook/pmd/section1/pmd144.htm)을 참고했다. 아래의 구간 길이·문턱은 Runograph의 제품 기준이며 그 자료가 검증한 수치가 아니다.

## 3. 출시 범위와 순서

| 단계               | 포함 범위                                                         | 완료 의미                                       |
| ------------------ | ----------------------------------------------------------------- | ----------------------------------------------- |
| A · 데이터 신뢰성  | 품질 정책, 시간/커버리지 구분, 긴 공백, 페이스 축, 지표별 제외    | 잘못 읽히던 기록을 재현하고 왜곡 없이 탐색 가능 |
| B · 핵심 분석      | 심박 중심 상세, 요약 재배치, 비슷한 속도의 심박 비교, 날짜별 근거 | 사용자가 변화와 사용한 기록을 한 흐름에서 확인  |
| C · 성장 질문 완성 | 비슷한 심박의 페이스, 운동시간·꾸준함, 전후반 유지력              | 다른 질문을 같은 지표로 포장하지 않고 각자 답함 |
| D · 재방문         | 선택형 로컬 보관, 새 ZIP 병합, 재열기                             | 기존 분석과 새 기록을 중복 없이 이어서 확인     |

**v0.2의 완료 범위는 A–C 전체다.** B까지만 구현하고 개편 완료라고 부르지 않는다. D는 후속 v0.3 범위로 확정하며 v0.2 출시를 막지 않는다. 사용자의 구현 지시에 따라 A–C를 완료했다.

이번 범위에 포함하지 않는 것: 종합 성장 점수, 자동 코칭·훈련 처방, VO₂max/최대심박/회복심박 추정, GPS 지도, 날씨 자동 보정, RunCast 데이터 연동, 동일 코스 PB 판정, 회귀 기반 체력 추정, 새 디자인 테마, PWA 아이콘 재제작.

## 4. 데이터와 품질 계약

### 4.1 원본·분석·표시를 분리

1. 정규화 원본: 실제 timestamp, 관측값, CSV 요약값과 출처를 보존한다.
2. 분석 입력: 유효 인접 구간, 안정 구간, 지표별 포함 여부를 만든다.
3. 표시 입력: 다운샘플링, 축 집중, 표시 보조선. 분석 입력으로 재사용하지 않는다.

현재의 시간 정보 없는 `PaceBin`은 새 성장 계산의 입력으로 사용하지 않는다. 원본 ZIP을 수정하거나 결측을 보간해서 관측 수를 늘리지 않는다.

### 4.2 품질 상태

`QualityIssue`는 code, 영향 지표, 근거, 대상 구간, 기본 처리, 사용자 설명을 가진다. 기록 전체에 정상/불량 하나만 붙이지 않는다.

| 상황                               | 기본 처리                                                                              |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| 파싱 불가·동일 시각 충돌·비유한 값 | 해당 필드/구간 계산 불가. 가능한 다른 값은 사용                                        |
| 매우 짧은 기록                     | CSV 운동시간 60초 미만은 `짧은 기록`. 원본 목록에 보존, 기본 추세와 운동 일수에서 제외 |
| 요약 시간·거리 신뢰성 확인 필요    | 요약 페이스와 해당 시간·거리의 일반 추세 사용 보류. 원본 합계에는 포함 여부를 명시     |
| 긴 관측 공백                       | 선과 연속시간을 끊고 구간별 사용. 전체 기록을 일괄 삭제하지 않음                       |
| 심박 없음                          | 운동량·페이스는 사용 가능. 심박 관련 비교만 불가                                       |
| 기기/시간대 불명                   | 불명 상태를 유지. 다른 출처와 조용히 같은 조건으로 합치지 않음                         |
| 사용자 제외                        | 분석별 제외 범위를 적용하고 되돌리기 제공                                              |

짧은 기록은 오류 확정이 아니다. 사용자가 유효한 분할 운동으로 포함할 수 있으며 변경 사실을 표시한다. 읽을 수 없는 값이나 센서 공백을 수동 포함으로 유효 관측으로 바꾸지는 않는다.

요약 신뢰성 검사는 다음을 각각 코드로 반환한다. 속도 상한을 근거로 운동 자체를 삭제하지 않는다.

- duration이 end−start보다 `max(60초, 경과시간의 5%)` 이상 큼: 시간 불일치.
- 시간/거리로 얻은 페이스가 2:00/km보다 빠름: 요약 페이스 확인 필요.
- 유효 상세 속도 10개 이상에서 요약 평균속도가 상세 최고속도의 1.5배 초과: 요약·상세 속도 확인 필요. 상세가 전체 운동을 대표하지 않을 수 있다는 근거 한계도 남긴다.
- duration과 end−start의 차이만으로 잘못된 duration이라 판단하지 않는다. 일시정지 가능성을 남긴다.

의심스러운 시간·거리 비율에서 어느 필드가 잘못됐는지 확정할 수 없으면 둘을 보정하지 않는다. 기본 일반 추세에서는 둘 다 보류하고 `삼성 원본 값`에서 계속 확인한다. 상세가 유효한 구간은 별도 심박/속도 분석에 사용할 수 있다.

### 4.3 집계와 날짜

- `가져온 기록 N회`와 `이 지표에 사용한 M회`를 구분한다. 의료적 의미의 정상 러닝 수를 만들지 않는다.
- 기본 운동량은 해당 필드의 품질 검사를 통과한 값으로 계산한다. `원본 합계 보기`에서 보류된 값을 포함한 CSV 합계와 차이를 확인한다.
- 평균 페이스는 시간·거리가 모두 적격인 **동일 집합**의 총 시간/총 거리. 두 합계를 서로 다른 집합에서 가져오지 않는다.
- 활동 일수는 기록 당시 현지 날짜의 중복 없는 수. 하루 여러 세션을 여러 날로 세지 않는다.
- 오프셋 불명 기록은 UTC 기준 임시 날짜임을 표시하고 현지 날짜별 주/월 성장 집계에서 기본 제외한다. 기록 목록과 비날짜 요약은 유지한다.
- 날짜 축은 실제 날짜 간격을 사용한다. 파일에 기록이 없는 주는 `기록 없음`이며 운동하지 않았다는 판정이 아니다.

### 4.4 세 가지 시간과 커버리지

`CSV 운동시간`, `시작부터의 실제 경과시간`, `유효 관측시간`을 별도 값으로 유지한다. 가장 긴 관측시간이나 마지막 timestamp를 운동시간으로 대체하지 않는다.

연결 가능한 인접 구간은 기존 원칙을 유지한다: `gapLimit = clamp(양수 관측 간격 중앙값 × 3, 3초, 60초)`. 양 끝에 필요한 지표가 있고 dt가 이 제한 이하일 때만 dt를 가중치로 쓴다. 구간 경계와 겹치는 부분의 시간만 배분하고 마지막 점을 종료까지 연장하지 않는다.

- 상세 전체: 전체 경과시간 기준 관측 비율과 관측 분 수를 구분해 표시한다.
- 선택 구간: 그 구간의 실제 길이를 분모로 한다. 양 끝 결측을 잘라 분모를 줄이지 않는다.
- 성장 창: 정해진 60초/120초를 분모로 한다. 페이스에 가까운 점만 분모로 써서 커버리지를 높이지 않는다.
- 심박/속도/케이던스와 심박·속도 동시 관측은 각각 별도 커버리지를 가진다.

## 5. 화면 스펙

### 5.1 요약

상단 순서는 `현재 비교 기간 → 핵심 관측 최대 2개 → 작은 근거 그래프 → 운동량 → 최근 기록`이다. 큰 영문 문구와 감성 제목을 제거한다.

- 첫 질문은 기본 `비슷한 속도에서 심박이 달라졌나?`다. 성립하면 관측 차이·두 기간·러닝 수를 먼저 보여준다.
- 성립하지 않으면 부족한 이유를 짧게 보여주고 운동량 요약을 제공한다. 더 좋아 보이는 페이스/기간을 찾아 결론을 대체하지 않는다.
- 두 번째 관측은 운동 일수·시간 같은 수행량 변화로 고정한다. 변화량이 가장 큰 통계를 골라 올리지 않는다.
- 관측을 누르면 같은 기간·질문·기기·페이스가 설정된 성장 화면으로 이동한다.
- 국소 심박 급변, 케이던스 유사성 등은 홈 대표 카드에서 내리고 해당 러닝의 근거 탐색으로 옮긴다.

### 5.2 기록 목록

날짜, 거리, 운동시간, 요약 페이스, 심박, 품질 상태를 읽을 수 있는 행 구조를 유지한다. 보류된 페이스를 일반 숫자와 동일하게 강조하지 않는다. `전체 / 비교에 사용 가능 / 확인 필요` 필터, 날짜·거리 검색, 최신/과거순을 제공한다. 일반 목록에서 짧은 기록을 삭제하지 않는다.

### 5.3 러닝 상세

`날짜·거리·시간 → 간결한 상태/보기 조작 → 큰 심박 차트 → 같은 시간축 페이스 → 구간 요약 → 관찰·추가 지표` 순서로 둔다.

- 심박 차트 기본 높이 240px, 페이스 110px. 케이던스는 `추가 지표`에서 펼친다. 심박이 없으면 페이스가 주 차트가 된다.
- 390×844 화면에서 심박 차트의 시작은 상단 300px 이내, 첫 뷰포트에서 전체 심박 흐름과 시간축이 보여야 한다. 보기 전환 후에도 유지한다.
- 나눠/겹쳐 보기 모두 심박·페이스를 즉시 확인한다. 겹쳐 보기의 케이던스도 활성화할 수 있다. 원래의 3개 지표 동시 탐색 기능은 유지한다.
- 독립 Y축을 쓰는 겹쳐 보기는 `변화 시점 비교`라고 설명한다. 눈금 지표만 바꿀 때 선 위치를 바꾸지 않는다.
- 확대 범위, 선택 timestamp, 고정 상태는 보기 전환·케이던스 펼침·축 모드 전환에도 유지한다.
- 빈 커서 안내 상자가 그래프 위 공간을 차지하지 않게 한다. 시점 값은 차트 바로 아래의 한 줄/작은 표로 제공한다.
- 기본 구간 요약은 주 표시 범위를 실제 경과시간 기준 3등분한 초반/중간/후반이다. 각 구간의 시간가중 심박, 시간가중 속도를 환산한 페이스, 관측시간·비율을 함께 표시한다. 공백을 제거해 3등분하지 않는다.
- 구간의 해당 지표 커버리지 70% 미만이면 대표값 대신 부족 상태. 심박 한 지표가 부족해도 다른 지표까지 숨기지 않는다.
- 관찰을 탭하면 해당 범위로 확대하고 표시 보조선 대신 원본 근거도 바로 확인한다.

### 5.4 그래프 축과 공백

**X축:** 기본은 실제 경과시간이다. 다만 `max(10분, gapLimit × 10)`보다 큰 공백으로 나눈 관측 묶음 중 하나가 전체 유효 관측시간의 80% 이상이고, 그 묶음이 5분 이상이며 전체 범위가 그 묶음의 3배보다 길면 해당 묶음에 기본 초점을 맞춘다. 심박·속도 중 하나라도 유효한 인접 구간의 합집합으로 관측시간을 계산한다.

집중 표시에는 `주 관측 구간`, 화면 밖 구간/점 수, 공백 길이, 전체 경과시간, `전체 시간 보기`를 붙인다. 전체 개요에서도 실제 공백을 유지한다. 다른 관측 묶음을 선택할 수 있고 숫자 축을 몰래 이어 붙이지 않는다. 조건 미달이면 전체 범위를 유지한다.

**페이스 Y축:** 현재 주 표시 범위에서 speed≥1.8m/s인 관측이 3분 이상이고 유효 속도 관측시간의 60% 이상일 때, 그 관측의 시간가중 P2–P98에 양쪽 15초/km 여백을 둔 범위를 기본으로 쓴다. 최소 폭 60초/km를 보장하고 15초 단위로 바깥쪽 반올림한다. 조건 미달이면 전체 범위다. 이는 표시 규칙이며 분석에서 해당 값을 버리는 규칙이 아니다.

바깥값은 경계 삼각형/바깥 구간 표시로 알리고 실제 값과 시각을 확인하게 한다. 바깥값을 경계의 정상 점인 것처럼 그리거나 연결하지 않는다. `전체 페이스 범위`로 전환 가능하다. 빠른 페이스가 위쪽이다.

심박 축은 유효 관측 범위에 최소 5bpm 여백, 최소 축 폭 20bpm을 둔다. Y축 범위를 명시하며 0 시작을 강요하지 않는다. 확대 시 각 모드의 Y축을 고정한다. 여러 기록을 비교할 때는 공통 축을 사용한다.

X축 눈금은 1/2/5/10/15/30/60분 중 화면 폭에 맞는 간격을 택한다. 시작·중간·끝만 기계적으로 3등분하지 않는다.

### 5.5 원본과 표시용 추세

심박은 얇은 원본 관측선과 구분되는 60초 이동 중앙값 선을 제공한다. 후자는 `표시용 추세`이며 끌 수 있다. 시간가중 중앙값으로 계산하고 ±30초 창을 사용한다. 같은 연속 관측 묶음 안에서만 계산하고 창의 실제 길이 대비 70% 이상 및 유효 30초 이상일 때만 그린다. 공백 주변에서 다음 묶음을 끌어오지 않는다.

툴팁·구간 통계·성장 계산은 원본 기반이다. 다운샘플링은 피크와 결측 경계를 보존한다. 기본 보간은 직선이며 없는 측정값이나 새 피크를 만들지 않는다.

터치 탭 고정, 수평 탐색, 세로 스크롤, 구간 핸들, 키보드/시간 입력을 제공한다. 공백 내부를 탭하면 `관측 없음`을 보여주며 멀리 떨어진 표본을 현재 시점처럼 선택하지 않는다. 화면용 점이 아니라 원본 timestamp로 시점을 찾는다. 핀치는 v0.2 필수가 아니다.

## 6. 성장 분석: 기본 비교 모델

### 6.1 기간과 조건

- 기본 기준일 T는 가져온 적격 기록의 최신 현지 날짜. 브라우저를 연 날짜를 자동 기준으로 쓰지 않는다.
- 최근 `[T−27일, T]`, 이전 `[T−55일, T−28일]`의 서로 겹치지 않는 28일을 비교한다. 날짜는 양 끝을 포함한다.
- 14/28/56일 및 사용자 지정의 같은 길이 기간을 지원한다. 부족하다고 기간을 자동으로 늘리지 않고 사용자가 선택하게 한다.
- 기본 운동 구간은 시작 5–20분. 5분 단위 구간(5–10, 10–15, 15–20분)을 두 기간에서 같은 비중으로 맞춘다. 다른 구간 선택은 고급 조건에 둔다.
- 기기는 두 기간 공통 그룹 중 관측 지원량이 가장 큰 하나를 제안한다. 원본 ID 대신 로컬 `기기 A/B`를 사용하고 모델명을 추정하지 않는다.
- 공통 기기가 없거나 출처가 불명이면 관측 자체를 보여주되 조건 일치 결과로 강조하지 않는다. `모든 기기`는 사용자가 선택할 수 있고 혼합 상태가 계속 보인다.
- 기온·경사·수면·착용 상태는 보정하지 않는다. 상단에는 `날씨·코스는 맞추지 않은 관측 비교`를 짧게 표시하고 상세 한계는 펼침에 둔다.

### 6.2 안정 관측 창

다음 수치는 v0.2의 **검증할 초기 기본값**이다. 구현자가 결과 개수를 늘리기 위해 임의 조정하지 않는다. 변경은 계산 버전, 근거, 전체 데이터의 전후 비교를 기록해야 한다.

1. 기록 시작 기준 60초 격자로 분석 창 `[t, t+60초)`를 만든다. 분석용 관측 구간끼리는 겹치지 않는다.
2. 앞 60초와 합친 `[t−60초, t+60초)` 120초를 속도 안정성 문맥으로 사용한다. 문맥도 시작 5분 이후여야 하므로 첫 후보 분석 창은 6–7분이다.
3. 문맥의 속도 관측 커버리지 ≥80%, 시간가중 속도 변동계수 ≤8%, 전·후 60초 평균속도 차이 ≤5%.
4. 문맥 안에 gapLimit 초과 공백, speed<1.8m/s 관측, 인접 속도 변화 >20%가 있으면 해당 창은 제외한다. 높은 심박 자체는 제외 사유가 아니다.
5. 분석 창의 심박·속도 동시 커버리지 ≥80%, 서로 다른 실제 동시 관측 timestamp ≥4개.
6. 선택한 운동 구간 안에 적격 분석 창 3개 이상, 동시 관측시간 합계 ≥180초인 러닝이 기본 비교 후보가 된다. 이 후보 선정은 목표 페이스를 움직여도 바뀌지 않는다.

각 창은 원본 동시 관측 구간의 시간가중 평균 HR·속도, 속도 편차, 관측시간, 표본 수, elapsed 범위, 기기 그룹, 원본 연결을 보관한다. 심박을 임의로 몇 초 앞뒤로 이동시키지 않는다. 이 필터가 생리적 정상상태를 보장한다고 설명하지 않는다.

### 6.3 비슷한 속도의 심박: 연속 가중 방식

내부 계산은 속도(m/s), 화면은 페이스(초/km)다. 목표 페이스 p₀에서 v₀=1000/p₀. 기본 속도 폭 h=0.08×v₀이며 가까운 안정 창의 영향력을 다음처럼 줄인다.

`u = |창 평균속도 − v₀| / h`

`K(u) = (1 − u³)³ (0≤u<1), 그 밖은 0`

경계에서 영향력이 부드럽게 0이 된다. 1초 단위 bin이나 ±15초 구간을 비교 경계로 쓰지 않는다. 표시 반올림은 계산 이후에만 한다. 화면에는 `7:00 부근`처럼 목표와 실제 사용 속도 범위를 함께 보여준다. 8% 폭은 ±8% 페이스와 같지 않으므로 실제 환산 범위를 표시한다.

**긴 러닝/고밀도 센서의 과대 반영 방지:** 러닝 s, 5분 구간 j의 적격 창 관측시간 합을 Dₛⱼ라 한다. 각 창의 가중치는 `w = (해당 창 관측시간 / Dₛⱼ) × K(u)`다. 한 러닝의 한 구간 기여도 qₛⱼ=Σw는 최대 1이다. 속도가 먼 러닝의 작은 가중치를 다시 1로 키우지 않는다.

각 기간·5분 구간에서 `Hⱼ=Σ(w×HR)/Σw`를 계산하고, 두 기간에 공통으로 선택된 5분 구간들의 Hⱼ를 같은 비중으로 평균한다. 평균 속도와 평균 elapsed도 같은 가중치로 계산해 비교 조건을 검사한다. 목표에 대한 회귀 예측이 아니라 주변 실제 관측의 요약이다.

초기 조건 선택 시 양쪽에 지원되는 5분 구간을 정하고 표시한다. 적어도 2개 구간이 필요하다. 페이스 슬라이더를 움직이는 동안 구간 집합과 기기를 몰래 교체하지 않는다. 지원이 사라지면 부족 상태로 바꾼다. `조건 다시 제안`은 명시적 동작이다.

**동일 속도로 읽어도 되는지 검사:** 각 사용 5분 구간에서 두 기간의 가중 평균속도 차이가 두 값 평균 대비 1% 이하, 가중 평균 elapsed 차이가 60초 이하일 때만 관측 차이를 주 결과로 제시한다. 맞지 않으면 두 관측값과 실제 페이스/시점 차이를 보여주고 `비교 조건 차이`로 표시한다. 이를 회귀로 억지 보정하거나 같은 조건의 향상으로 서술하지 않는다.

### 6.4 지원량과 결과 상태

대상 러닝 수, 고유 운동 일수, 실제 동시 관측 수·분, 유효 러닝 수를 별도로 계산한다. 유효 러닝 수는 러닝별 기여도 q를 이용한 `(Σq)²/Σ(q²)`이며 의료적 신뢰도 점수가 아니다. 전체 q는 사용 5분 구간의 qₛⱼ를 동일 비중으로 평균한다.

| 상태           | 조건과 화면                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 비교 가능      | 각 기간 실제 5회·3일 이상, 전체 유효 러닝 수 ≥5, 사용 구간마다 유효 러닝 수 ≥3, 각 기간 가중 관측시간 Σ(dt×K) ≥10분. 조건 일치 검사도 통과        |
| 참고 관측      | 각 기간 실제 3회·2일 이상, 전체 유효 러닝 수 ≥3, 사용 구간마다 ≥2, 각 기간 가중 관측시간 ≥5분. 대표값은 약하게 표시하고 홈 결론으로 사용하지 않음 |
| 비교 조건 차이 | 지원량은 있으나 기기·속도·elapsed 조건이 맞지 않음. 양쪽 값과 무엇이 다른지 표시                                                                  |
| 데이터 부족    | 위 조건 미달. 원본 점과 부족한 항목을 표시하고 차이 결론·추세선을 만들지 않음                                                                     |
| 설정에 민감    | 아래 민감도 검사에서 방향이 바뀌거나 지원량/조건 일치 상태가 바뀜. 기본 숫자와 변동 범위를 보여주되 단정 문구 금지                                |

기본 목표는 양 기간 공통 관측 범위에서 유효 러닝 수의 작은 쪽을 가장 크게 하는 페이스를 선택한다. 동률이면 공통 가중 관측시간, 이후 전체 속도 중앙값과의 가까운 순으로 결정한다. 결과 HR이나 개선 폭을 선택 기준에 사용하지 않는다.

관측 범위는 두 기간 각각의 안정 창 속도 시간가중 P10–P90의 교집합으로 제한한다. 이 범위 밖에는 결과를 연장하지 않는다. 겹침이 없으면 비교 불가다.

### 6.5 민감도, 분포와 표현

- 폭 6%/8%/10%로 계산한 결과, 러닝 하나씩 제외한 결과를 진단한다. 같은 구간·기기를 유지한다. 반올림 전 차이의 부호가 바뀌거나 결과 상태가 바뀌면 `설정에 민감`이다.
- 센서 점 수를 독립 표본 수로 삼지 않는다. v0.2에서 p값, 유의성 배지, 부트스트랩 신뢰구간을 제공하지 않는다.
- 날짜별 점은 해당 러닝의 선택 구간 전체에서 `Σ(w×HR)/Σw`로 얻은 주변 관측 요약이다. 점의 강조 정도로 기여도 q를 구분하며 탭하면 실제 창·시각·값을 확인한다. 기간 대표값은 5분 구간을 동일 비중으로 맞춘 값이므로 날짜별 점의 단순 평균과 다를 수 있음을 계산 설명에 명시한다.
- 분포는 러닝별 점에 러닝 기여도 q를 가중한 P25–P75(IQR)다. `러닝별 관측 편차`로 표시하고 계산 설명에 가중 방식을 밝힌다. 기간 대표값의 신뢰구간으로 표시하지 않는다. 기간 대표값은 위의 가중 평균이며 이전의 중앙값의 중앙값을 계속 혼용하지 않는다.
- 기본 그래프는 실제 날짜 축의 러닝별 점 + 두 기간 대표값/분포. 작은 월별 평균점만 잇는 그래프를 기본으로 쓰지 않는다. 부족 기간이나 장기간 기록 공백을 선으로 연결하지 않는다.
- 문구는 `비슷한 속도 부근에서 최근 관측 심박이 낮았습니다` 수준이다. `체력이 X% 향상`, `더 편해짐 확정`, `훈련 효과`로 바꾸지 않는다. 차이는 숫자로 보여주되 좋은/나쁜 등급을 만들지 않는다.

### 6.6 비슷한 심박에서의 페이스

별도 질문으로 제공한다. 앞의 속도→심박 결과를 역산하지 않는다.

- 같은 안정 창, 기간, 기기, 운동 구간 계약을 사용한다.
- 목표 HR 주변 tri-cube 가중치, 기본 폭 10bpm. 민감도는 8/10/12bpm.
- 평균 속도를 구한 후 `1000/평균속도`로 페이스를 환산한다. 순간 페이스의 단순 산술평균은 사용하지 않는다.
- 공통 HR P10–P90 범위 안에서만 계산한다. 실제 가중 평균 HR 차이 ≤2bpm, elapsed 차이 ≤60초인지 검사한다. 지원량 상태는 6.4와 같다.
- `비슷한 심박에서 관측 페이스가 빨라짐/느려짐`으로 표현한다. 같은 심박을 같은 주관적 노력이나 훈련 강도로 단정하지 않는다. 임의의 최대심박 Zone은 만들지 않는다.

## 7. 다른 성장 질문

| 질문              | v0.2 결과                                                                         | 해석 경계                                                 |
| ----------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 더 오래 달렸나    | 기록당 CSV 운동시간 중앙값/IQR, 관측상 이어진 달리기 구간 길이의 분포를 별도 표시 | 기록시간 증가를 같은 강도의 지구력 향상으로 표현하지 않음 |
| 후반에도 유지했나 | 같은 기록의 전후반 심박 차이와 페이스 변화, 사용 구간                             | 속도·시간이 다르면 조건 차이를 표시                       |
| 꾸준히 달렸나     | 주별 고유 운동 일수, 시간, 거리, 기록 수                                          | 진행 중 주와 완료 주 구분, 기록 부재와 운동 부재 구별     |

관측상 이어진 달리기 구간은 유효 속도가 1.8m/s 이상으로 인접 연결되는 구간으로 한정하고 `달리기 추정`이라고 부른다. 결측·긴 공백·그 미만 속도에서 끊는다. 그 길이를 실제 무정지 운동시간으로 확정하지 않는다. 같은 강도에서의 최대 지속능력 비교는 후속 범위이며 운동시간 그래프로 대신 주장하지 않는다.

**일반 전후반 비교:** 선택한 하나의 관측 묶음에서 시작 5분을 제외한 실제 범위를 절반으로 나눈다. 각 절반 ≥5분, 동시 관측 커버리지 ≥70%이면 시간가중 HR과 평균속도 환산 페이스를 보여준다. 각 절반의 길이·관측시간·속도 편차를 함께 표시한다. 두 속도 차이가 5%를 넘으면 `페이스도 달라진 전후반`으로 설명한다. 서로 다른 길이 러닝을 한 줄의 유지력 점수로 묶지 않는다.

**엄격한 드리프트:** 기존 연속 20분/커버리지 80%/두 절반 속도 차이 5% 이내 조건과 효율 수식은 고급 지표로 유지한다. 단 하나만 있으면 한 기록의 관찰만 보여주고 성장 추세는 만들지 않는다. 일반 전후반 비교를 드리프트라고 이름 붙이지 않는다.

꾸준함 그래프는 0 기준 막대이며 주 경계는 기록 현지 날짜의 월요일이다. 진행 중 주·월을 전체 이전 주·월과 직접 증감률로 비교하지 않는다. 요약의 기간 증감은 동일 길이 기간을 사용한다.

## 8. 관찰과 근거 연결

기존 심박 급변·사용자 기준 이상·케이던스 유사성·감속 뒤 심박 변화는 상세 탐색에 유지한다. 계산 가능한 것과 검출된 것이 없는 상태를 구별한다.

모든 결과에 `EvidenceRef`를 제공한다: 내부 sessionKey, 실제 elapsed 범위, 사용 지표, 원본/관측 요약 출처, 제외 사유, 계산 버전. 결과 → 사용 러닝 목록 → 해당 구간 확대가 이어져야 한다. 돌아오면 비교 조건·스크롤 위치를 복원한다.

새 성장 기준에 맞지 않는 기존 페이스 bin 기반 `평소 대비 다른 심박`은 그대로 재사용하지 않는다. 새 기준으로 같은 기기·구간의 과거 비교가 가능할 때만 다시 제공하고 그전에는 상세에 기존 결과를 섞지 않는다.

요약값, 실제 관측값, 주변 관측의 가중 요약, 표시용 추세선은 서로 다른 출처로 구분한다. 심박/케이던스 패턴을 센서 오류나 질병의 확정 증거로 표시하지 않는다.

## 9. 재방문 정책: 후속 v0.3

v0.2는 기존 메모리 전용 기본값을 유지한다. v0.3에서 `이 기기에 기록 보관`을 사용자가 켰을 때만 IndexedDB에 정규화 기록·필요한 상세·계산 버전·설정을 저장한다. ZIP 원본, GPS, 프로필, 사진, 원본 메모는 저장하지 않는다.

- 원본 UUID/기기 ID는 설치별 salt를 쓰는 로컬 불투명 키로 변환해 중복과 동일 기기를 연결한다. 외부 로그·리포트에는 내보내지 않는다. 이 키와 건강 기록을 비민감 데이터라고 부르지 않는다.
- 같은 UUID 키는 유효 update_time이 더 최신이면 교체, 동일 시각 동일 내용은 무시, 동일 시각 다른 내용은 충돌 보류. UUID 없는 기록은 정규화 내용의 정확 일치만 자동 중복 제거하고 비슷한 기록은 후보로 남긴다.
- 병합은 추가/갱신/충돌/유지 수를 미리 보여준다. 중단·용량 초과·실패 시 이전 데이터가 남도록 원자적 갱신한다. 신규 ZIP에 없는 예전 기록을 자동 삭제하지 않는다.
- 원본을 저장하지 않아도 계산 버전 변경 시 저장된 정규화 관측으로 재계산 가능해야 한다. 필수 정보가 부족한 이전 스키마는 재선택을 요청하며 새 버전 결과처럼 사용하지 않는다.
- 보관 중 여부, 마지막 기록 날짜, 저장 용량, 전체 삭제를 제공한다. 저장 해제는 보관 데이터 삭제를 동반한다. 설정 확인은 앱 사용자 흐름의 일부다.
- 브라우저 저장소가 지워질 수 있음을 설명한다. 서버 백업·동기화는 없다.
- 오프라인 새 실행을 지원하려면 앱 셸 캐시·갱신 정책을 별도 구현/검증한다. IndexedDB 저장만으로 오프라인 지원을 선언하지 않는다. 건강 데이터는 Service Worker 캐시에 넣지 않는다.

실제 ZIP 회귀 검증은 로컬에서만 수행한다. 두 진단이 재현한 품질·긴 공백·페이스 축·구간 경계 민감도 사례를 다시 확인하고, 변경 후 각 필터 단계의 대상 러닝/창/관측시간·제외 사유 분포를 남긴다. **기존 진단에서 나온 월별 차이 수치를 새 알고리즘의 정답으로 고정하지 않는다.**

안정 창 기본값의 검증은 결과 개선 폭을 보지 않고 수행한다. 문맥 90/120/180초, 속도 변동 5/8/12%, 폭 6/8/10%에서 지원량·비교 상태·방향 민감도를 기록한다. 기본값 변경이 필요하면 과잉 제외/불안정 사례와 변경 근거를 설계 문서에 반영한다. 결과가 적다고 조용히 느슨하게 하지 않는다.

`npm test`, `npm run build`, 해당 흐름의 Playwright 검증을 수행한다. 실기기 Samsung Internet/Android Chrome/iPhone Safari에서는 파일 선택·첫 차트·스크롤·구간 조작·취소·메모리 압박을 확인한다. 자동화 WebKit을 실기기 Safari 검증으로 대체하지 않는다.

성능 목표: 상세 데이터 준비 후 첫 차트 500ms 이내, 커서 반응 100ms 이내, 비교 조건 확정 후 결과 갱신 500ms 이내. 측정 기기·데이터 크기와 p95를 기록하며 아직 달성한 수치로 표현하지 않는다. ZIP 처리시간은 별도로 측정한다.
