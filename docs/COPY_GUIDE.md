# Runograph 문구 원칙과 검토 기록

2026-10-08. 시작·처리·요약·목록·상세·성장·오류·리포트·설치·접근성 문구를 검토하고 제품에 반영했다. 사용자의 추가 지시에 따라 **쉽게 쓰되 지나치게 풀어 설명하지 않는 것**을 기준으로 삼았다. 계산 기준과 적격 조건은 바꾸지 않았다.

## 적용 원칙

[토스의 라이팅 원칙](https://toss.tech/article/21022)에서 명확함·간결함·일상적인 표현·사용자 존중을 참고했다. [배민의 UX 라이팅 사례](https://bcut.baemin.com/6287/)에서는 같은 정보도 사용자의 목적과 다음 행동에 맞춰 써야 한다는 접근을 참고했다. 두 브랜드의 말투나 유머를 그대로 옮기기보다 Runograph의 차분한 기록장에 맞게 적용했다.

- 질문 다음에 답을 쓴다. 답에서 질문을 길게 반복하지 않는다.
- 제목·라벨·버튼은 짧게, 설명·안내는 자연스러운 해요체로 쓴다. 모든 라벨을 문장으로 만들지 않는다.
- 러닝에서 익숙한 페이스·심박·케이던스·중앙값은 유지한다. 낯선 계산 개념은 관련 펼침 영역에서 짧게 설명한다.
- 버튼은 실제 행동을 드러낸다. 보기·제외·저장·전체 복귀를 구분하고 토글은 다음 행동을 표시한다.
- 조건 차이·부족 자료·설정 영향을 숨기지 않는다. 기록상의 변화를 체력 향상이나 건강 진단으로 바꾸어 말하지 않는다.

## 용어 기준

| 맥락                        | 표현                   | 판단                                              |
| --------------------------- | ---------------------- | ------------------------------------------------- |
| 센서가 기록한 값            | 측정값, 시간별 측정값  | 관측·상세 표본보다 바로 이해할 수 있음            |
| 운동 종류                   | 러닝                   | 달리기는 동작 설명에 사용                         |
| HR / pace / cadence         | 심박·페이스·케이던스   | 익숙한 러닝 용어 유지, bpm·/km·회/분 병기         |
| median                      | 중앙값, 중앙 페이스    | ‘중간 페이스’로 바꾸지 않고 필요할 때만 정의      |
| 측정 커버리지               | 측정 비율              | ‘심박 측정 12분 · 80%’처럼 대상과 함께 표시       |
| 대표값                      | 평균                   | 비교 평균의 가중 방식은 계산 설명에 표시          |
| effective n / weighted time | 유효 기록·가중 시간    | 실제 횟수·시간과 구별하고 펼침 영역에서 의미 설명 |
| IQR                         | 기록별 범위 (중앙 50%) | 평균의 오차 범위로 오해하지 않도록 계산 설명 보완 |
| 표시용 추세                 | 심박 흐름선            | 계산에 쓰지 않는 표시 보조선임을 설명             |
| 기기 출처 미상              | 기기 정보 없음         | 기기 모델을 추정하지 않음                         |
| partial period              | 마지막 기록까지        | 현재 날짜 기준 ‘진행 중’으로 오해하지 않음        |

## 화면별 판단

| 화면·상태       | 기존 문제                                              | 반영한 문구·방향                                                                                                              |
| --------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 시작            | 추상적인 슬로건과 영어가 기능을 설명하지 못함          | ‘내 러닝의 변화를 한눈에.’ + ‘심박과 페이스를 함께 보고, 지난 기록과 비교해 보세요.’                                          |
| 파일 선택       | 선택 버튼의 목적이 약함                                | ‘삼성헬스 ZIP 불러오기’. 압축 해제 없이 사용하며 재열기에는 파일이 필요함을 안내                                              |
| 처리            | CSV·JSON 같은 구현 용어 노출                           | 파일 확인·러닝 읽기·분석으로 실제 진행을 표시                                                                                 |
| 요약            | 기간 대표값·원본 집계 용어가 앞섬                      | 질문 → 최근 변화 → 이전보다 낮음/높음·빨라짐/느려짐 → 기록 수 → 그래프                                                        |
| 차이 숫자       | 음수와 ‘최근 − 이전’을 해석해야 함                     | 절댓값과 방향을 함께 표시. 원래 부호는 리포트·계산 확인에서 유지. 반올림해 0이 되는 미세한 차이는 낮음/높음으로 단정하지 않음 |
| 비교 상태       | ‘설정에 민감’만으로 이유를 알기 어려움                 | ‘설정 영향 있음’ / ‘설정에 따라 결과가 달라져요.’                                                                             |
| 조건 불일치     | 기기 차이인데 속도 차이로 설명할 가능성                | 실제 결과의 조건 사유를 표시                                                                                                  |
| 기록 부족       | 어려운 용어로 부족 상태를 반복                         | ‘이 조건에서는 비교할 기록이 부족해요.’ + 해당 조건의 사유                                                                    |
| 목록            | ‘상세 없음’, ‘분석 제한’의 대상이 모호함               | ‘시간별 측정값 없음’, ‘일부 분석만 완료’. 시간·거리 확인 필요와 비교 제외를 구분                                              |
| 상세            | 관측·독립 Y축·추세 등 전문 표현이 많음                 | 측정 시점·왼쪽 눈금·심박 흐름선. 나눠 보기/겹쳐 보기·페이스·케이던스는 유지                                                   |
| 긴 공백         | ‘관측 묶음’의 목적이 모호함                            | ‘긴 공백이 있어요. 볼 구간을 골라주세요.’ + 측정 구간 선택                                                                    |
| 원본·설정       | 포함 체크박스가 길고 딱딱함                            | ‘총 거리·운동시간 계산에서 제외’, ‘분할 기록으로 합계에 포함’, ‘지난 기록과 비교할 때 제외’                                   |
| 성장 근거       | ‘사용한 러닝과 실제 구간’, ‘지원량’처럼 내부 명칭 사용 | ‘비교에 쓴 러닝’, ‘비교에 쓴 구간·기록 수’, ‘이 러닝 빼고 비교’                                                               |
| 운동시간·꾸준함 | 질문의 범위와 중앙값 설명이 불명확                     | ‘한 번에 더 오래 달렸나요?’, ‘얼마나 꾸준히 달렸나요?’. 운동시간/연속 달리기는 따로 표시                                      |
| 전후반          | 엄격한 드리프트가 일반 비교와 혼재                     | 전후반의 심박·페이스를 먼저, ‘심박 효율 변화 (드리프트)’는 펼침에 유지                                                        |
| 오류            | 형식·경로·중첩 같은 원인만 전달                        | 읽지 못한 대상과 가능한 다음 행동을 안내. 사용자의 잘못으로 단정하지 않음                                                     |
| 저장·설치       | JSON·UUID·메모리 설명이 먼저 등장                      | ‘분석 결과 저장’ → 파일에 담길 내용 → ‘JSON 파일로 저장’. 새로고침·재열기 조건을 명확히 안내                                  |
| 접근성          | 화면 라벨과 접근성 이름이 달라질 수 있음               | 버튼·필터·슬라이더의 이름과 화면 표현을 함께 수정                                                                             |

공통 성장 질문은 `src/core/copy.ts`에서 관리해 요약과 성장 화면이 같은 말을 쓰도록 했다. 개인정보 안내와 계산 조건은 실제 동작을 기준으로 유지했다. 문구에 의존하는 기존 브라우저 테스트의 이름을 갱신하고, 비교 숫자의 방향 표시도 확인한다.
